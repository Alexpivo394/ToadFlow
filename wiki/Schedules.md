# Расписания

Расписание отвечает на вопросы: **какую задачу** выполнить, **над какими моделями**, **куда** положить результат и **как часто**. Задач две: **выгрузка RVT / NWC** и **проверка LOI** — заполнение параметров по профилю ParamChecker. Список расписаний показывает следующий запуск, автора и того, кто менял расписание последним; расписания проверки помечены **LOI**.

Создавать и менять расписания могут операторы и администраторы.

## Вкладка «Настройка»

| Поле | Что задаёт |
|---|---|
| **Название** | Имя в списке и в истории; подставляется в папку результатов как `{расписание}` |
| **Задача** | **Выгрузка RVT / NWC** или **Проверка LOI**. От неё зависят вкладка параметров и колонки на вкладке «Модели» |
| **Источник** | Revit Server или сетевая папка из **Настройки → Источники** |
| **Папка результатов** | Куда класть RVT и NWC или отчёты LOI. Подстановки: `{расписание}`, `{дата}` (ГГГГ-ММ-ДД), `{время}` (ЧЧ-ММ) — по часовому поясу из **Настройки → Общие**. Пример: `\nas\Выгрузки\{расписание}\{дата}` |
| **Когда** | **По дням недели** в заданное время, **каждые N часов** начиная с заданного времени или **один раз** |
| **Приоритет** | Низкий, обычный или высокий — кто первым получает свободный Revit |
| **Таймаут на модель, мин** | Дольше этого модель не обрабатывается: Revit убивается, модель считается упавшей |
| **Повторять упавшие** | Сколько раз повторить модель, если упал или завис Revit либо пропала связь с агентом. Ошибки самой модели (нет 3D-вида, модель повреждена) не повторяются |

Выключенное расписание не запускается по времени, но его можно запустить вручную.

## Вкладка «Модели»

Дерево источника. Галочка на папке отмечает всё её содержимое. У выгрузки для каждой отмеченной модели и папки выбирается **RVT** и/или **NWC**; у проверки LOI форматов нет.

Флажок **«Добавлять новые модели из отмеченных папок»**: при каждом запуске папка разворачивается заново, и модели, появившиеся в ней позже, тоже обрабатываются. Без флажка обрабатывается только то, что было в папке при сохранении.

## Вкладка «Параметры RVT / NWC»

Для выгрузки: пресет выгрузки и переопределения его параметров только для этого расписания.

> [!NOTE]
> Модель с NWC берёт только агент, у которого для её версии Revit установлен Navisworks Exporter. Если такого агента нет, модель ждёт в очереди.

## Вкладка «Проверка LOI»

Для проверки LOI: профиль из **Настройки → Профили LOI** и отличия от него.

| Поле | Что задаёт |
|---|---|
| **Профиль проверки** | **По разделу модели** — одно расписание охватывает весь проект, у каждой модели — профиль её раздела из таблицы ниже. Или **один профиль** на всё расписание. Расписание с неготовым профилем (нет правил, у правила нет параметров или категорий) не сохраняется |
| **Профили разделов проекта** | Для «по разделу модели»: какой профиль у какого раздела **в этом проекте** — у ОВ в разных проектах профили разные. Раздел берётся из имени модели [справочником именования](Analytics#откуда-берутся-объект-и-раздел), ручные поправки моделей главнее. **Скопировать из расписания** — взять таблицу из расписания похожего проекта и поправить |
| **Остальные модели** | Модели, раздел которых не распознан или не назначен: проверяются выбранным профилем или пропускаются |
| **Исключения** | Модели, которым нужен другой профиль, — главнее раздела и профиля расписания. Модель задаётся именем без расширения |
| **Профили моделей** | Предпросмотр: какой профиль получит каждая отмеченная модель и почему — по разделу, исключение, для остальных или «пропускается». Модели из отмеченных папок появляются здесь после первого запуска |
| **Вид** | По умолчанию — как в профиле. Своё значение: имя вида, с которого собираются элементы; пусто — вся модель |
| **Не открывать РН, содержащие** | По умолчанию — как в профиле. Рабочие наборы с этим словом остаются закрытыми, их элементы не проверяются |
| **Не загружать связи** | Модель копируется во временную папку агента, в копии связи не загружаются — открытие быстрее |
| **В листах правил только элементы с пропусками** | Итоги считаются по всем элементам, а в листы попадают только незаполненные — отчёты по большим моделям в разы меньше |
| **Записывать итоги в аналитику ToadFlow** | Итоги попадают на страницу [Аналитика LOI](Analytics). Включено по умолчанию; не действует, если аналитика выключена во всём сервисе |
| **База для дашбордов** | Книга Excel (`.xlsx`), куда каждая проверенная модель дописывает итоги, — та же база, что ведёт ParamChecker, для Power BI. Подстановки — как у папки результатов. Пусто — база не ведётся |

Модель, которой не нашлось профиля (раздел не распознан или ему профиль не назначен, а для остальных моделей профиля нет), не проверяется: запуск помечается предупреждением со списком таких моделей и причиной.

На каждую модель в папке результатов появляется отчёт `<модель>_LOIReport.xlsx` — такой же, как у ParamChecker: лист «Сводка» с полнотой и заполненностью по правилам и параметрам и по листу на правило.

> [!NOTE]
> Базу для дашбордов одновременно дописывают несколько Revit, в том числе на разных машинах: запись идёт по очереди, через файл-замок `<база>.xlsx.lock` рядом. Если база открыта в Excel, модель всё равно проверяется, а в истории она помечается «с предупреждением».

После сохранения расписание предупреждает о том, что заведомо помешает работе: для версии Revit источника нет ни одного агента, или у моделей одинаковые имена файлов и они перезапишут друг друга в папке результатов.

## Вкладка «История изменений»

Кто и когда менял расписание и что именно поменялось: папку, модели, время, параметры задачи и так далее.

## Запуск вручную

Кнопка **«Запустить сейчас»** создаёт запуск сразу, не дожидаясь времени по расписанию. В истории такой запуск помечен именем того, кто его запустил.

## Версии Revit

Модель всегда открывается в Revit той версии, в которой она сохранена, и не обновляется. Для Revit Server версия задана в источнике; для сетевой папки агент читает её из каждого файла. Если ни на одном агенте нет нужной версии, модель ждёт в очереди с пометкой **«ждёт Revit 20NN»**.
