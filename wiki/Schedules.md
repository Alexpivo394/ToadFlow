# Расписания

Расписание — это ваше поручение ферме. В нём четыре ответа: **какую задачу** выполнить, **над какими моделями**, **куда** положить результат и **как часто**. Один раз объяснили — дальше оно делается само, пока вы не передумаете.

Задачу задаёт модуль, в котором расписание создано. Расписания живут внутри своего модуля и видят только своих:

| Где в меню | Что делает |
|---|---|
| **Выгрузка → Расписания** | Сохраняет модели в RVT и NWC в папку результатов |
| **Проверка LOI → Расписания** | Проверяет заполнение параметров по профилю ParamChecker, см. [Проверка LOI](LOI) |
| **Коллизии → Расписания выгрузки** (в настройке коллизий) | Выгружает геометрию моделей на сервер и прогоняет утверждённые проверки коллизий, см. [Коллизии](Clash#расписание-выгрузки) |

Вид задачи у созданного расписания не меняется: выгрузку нельзя переделать в проверку LOI. Нужна другая задача — создайте расписание в её модуле.

Список расписаний показывает следующий запуск, автора и того, кто менял расписание последним. Он сортируется щелчком по заголовку столбца, в нём есть поиск по названию и источнику и фильтр «включено / выключено».

Создавать и менять расписания могут координатор и администратор. Старые ссылки `/schedules/…` из закладок открывают расписание в его модуле — ничего не сломалось, просто всё переехало.

> [!TIP]
> На странице расписания есть кнопка **«Следить»**. Нажмите — и колокольчик сообщит, если запуск этого расписания закончится с ошибками. Создатель расписания следит за ним по умолчанию.

## Вкладка «Настройка»

| Поле | Что задаёт |
|---|---|
| **Название** | Имя в списке и в истории; подставляется в папку результатов как `{расписание}` |
| **Источник** | Revit Server или сетевая папка из **Ферма → Источники моделей** |
| **Папка результатов** | Куда класть RVT и NWC или отчёты LOI; выгрузке для коллизий не нужна. Пользователь агента должен иметь право записи в эту папку |
| **Когда** | **По дням недели** в заданное время, **каждые N часов** начиная с заданного времени или **один раз** |
| **Приоритет** | Низкий, обычный или высокий — кто первым получает свободный Revit |
| **Таймаут на модель, мин** | Дольше этого модель не обрабатывается: Revit убивается, модель считается упавшей |
| **Повторять упавшие** | Сколько раз повторить модель, если упал или завис Revit либо пропала связь с агентом |

**Подстановки в папке результатов.** Чтобы вчерашняя выгрузка не затёрлась сегодняшней:

| Пишете | Получаете |
|---|---|
| `{расписание}` | Название расписания |
| `{дата}` | `ГГГГ-ММ-ДД` |
| `{время}` | `ЧЧ-ММ` |

Пример: `\\nas\Выгрузки\{расписание}\{дата}` → `\\nas\Выгрузки\Северный NWC\2026-11-22`. Дата и время — по часовому поясу из **Администрирование → Сервер**.

**Про «Повторять упавшие».** Повторяется то, что могло пройти со второй попытки: упал или завис Revit, пропала связь. Ошибки самой модели — нет 3D-вида, модель повреждена — не повторяются. Вид сам собой не появится, сколько ни пробуй.

Выключенное расписание не запускается по времени, но его можно запустить вручную.

## Вкладка «Модели»

Дерево источника. Галочка на папке отмечает всё её содержимое. У выгрузки для каждой отмеченной модели и папки выбирается **RVT** и/или **NWC**; у проверки LOI форматов нет.

Флажок **«Добавлять новые модели из отмеченных папок автоматически»** решает, что будет с моделями, которые появятся в папке потом:

- **включён** — при каждом запуске папка разворачивается заново, новые модели тоже обрабатываются. Отметили папку проекта и забыли;
- **выключен** — обрабатывается только то, что было в папке при сохранении. Для тех, кто любит контроль.

## Вкладка «Параметры RVT / NWC»

Для выгрузки: пресет выгрузки и переопределения его параметров только для этого расписания. Что есть в пресете — [Где что настраивается → Пресеты выгрузки](Settings#пресеты-выгрузки).

> [!NOTE]
> Модель с NWC берёт только агент, у которого для её версии Revit установлен Navisworks Exporter. Если такого агента нет, модель ждёт в очереди — терпеливо и бесконечно.

## Вкладка «Проверка LOI»

Есть у расписаний с задачей **«Проверка LOI»**. Здесь решается, каким профилем проверять каждую модель и что делать с итогами. Как проверка устроена целиком — [Проверка LOI: как всё устроено](LOI).

### Профиль проверки

Поле **«Профиль проверки»** — главный выбор на вкладке:

| Вариант | Как работает | Когда подходит |
|---|---|---|
| **Один профиль** (разделы списка «Один на всё расписание — <группа>») | Все модели расписания проверяются этим профилем | В расписании модели одного раздела или у компании один профиль на всё |
| **По разделу модели** (группа «Для каждой модели») | Каждая модель получает профиль своего раздела из таблицы «Профили разделов проекта» | Одно расписание на весь проект, у разделов разные профили |

Во всех списках профили сгруппированы по [группам профилей](LOI-profiles#группы-профилей) и подписаны с группой — «Северный · ОВ»; в списке можно искать, начав вводить группу или имя.

Профиль, которому чего-то не хватает, помечен «(не готов)», а под полем красным написано, чего именно. Расписание с неготовым профилем не сохраняется — допишите профиль в **Проверка LOI → Профили** ([Профили LOI](LOI-profiles#готов-или-не-готов)).

### Профили разделов проекта

Появляется при варианте **«По разделу модели»**.

- **«+ Раздел»** добавляет строку: слева раздел (например «ОВ»), справа его профиль. Поле раздела подсказывает разделы из [справочника именования](Model-naming) и из уже проверенных моделей.
- Раздел модели ToadFlow берёт из её имени по справочнику; если для модели есть ручная поправка — из поправки.
- Один раздел нельзя назначить дважды.
- **«Скопировать из расписания…»** (справа над таблицей) берёт таблицу разделов и профиль для остальных моделей из другого расписания LOI. Удобно для похожих проектов: скопировать и поправить отличия.

> [!WARNING]
> Раздел в таблице и раздел из справочника сравниваются **без учёта регистра, но буква в букву**. «ОВ» (кириллица) и «OV» (латиница) — разные разделы, хотя глазами не отличить. Это причина №1 вопроса «почему модели пропускаются, я же всё настроил».

**Остальные модели** — что делать с моделями, раздел которых не распознан или не назначен в таблице: проверять выбранным профилем или **пропускать — с пометкой в истории запуска**.

### Исключения

Для моделей с характером: им нужен свой профиль, что бы ни говорил раздел или профиль расписания. Работают при обоих вариантах.

- **«+ Исключение»**, слева имя модели (без папок и расширения, регистр не важен; поле подсказывает отмеченные модели), справа профиль.
- Одной модели нельзя задать два исключения.

### Профили моделей

Таблица-предпросмотр: какой профиль получит каждая модель **с текущими, ещё не сохранёнными** настройками. Загляните сюда перед тем, как жать «Сохранить», — пять секунд сейчас экономят запуск вхолостую ночью.

| Пометка в колонке «Почему» | Значит |
|---|---|
| **исключение** | Профиль задан исключением для этой модели |
| **профиль расписания** | Выбран один профиль на всё расписание |
| **по разделу** | Раздел распознан и назначен в таблице разделов |
| **для остальных** | Раздел не распознан или не назначен, модель проверяется профилем остальных моделей |
| **пропускается** | Профиля нет — модель не будет проверена |

Порядок выбора профиля — кто первый, тот и прав:

```mermaid
flowchart LR
    A["Исключение<br/>для модели"] -->|нет| B["Один профиль<br/>расписания"] -->|нет| C["Профиль<br/>раздела"] -->|нет| D["Профиль<br/>остальных"] -->|нет| E(["Пропуск"])
```

В таблице — модели, отмеченные на вкладке «Модели» по одной. Модели из отмеченных папок появляются после первого запуска расписания.

### Что и как проверять

| Поле | Что задаёт |
|---|---|
| **Вид: своё для расписания** | Без флажка — вид из профиля каждой модели. С флажком — своё имя вида, с которого собираются элементы; пустое поле — вся модель |
| **Не открывать РН, содержащие: своё для расписания** | Без флажка — как в профиле. С флажком — своё слово: рабочие наборы с ним в имени остаются закрытыми, их элементы не проверяются |
| **Не загружать связи** | Модель копируется во временную папку агента, в копии связи не загружаются — открытие быстрее. Включено по умолчанию |
| **В листах правил только элементы с пропусками** | Итоги считаются по всем элементам, а в листы правил попадают только элементы с незаполненными параметрами — отчёты по большим моделям в разы меньше |
| **Записывать итоги в аналитику ToadFlow** | Итоги попадают на страницу [Аналитика LOI](Analytics). Включено по умолчанию; не действует, если аналитика выключена в **Проверка LOI → Настройка аналитики** |
| **База для дашбордов** | Путь к книге Excel (`.xlsx`), куда каждая проверенная модель дописывает итоги — та же база, что ведёт ParamChecker, для Power BI. Подстановки — как у папки результатов: `{расписание}`, `{дата}`, `{время}`. Пусто — база не ведётся |

### Что получается после запуска

- На каждую модель в папке результатов — отчёт `<модель>_LOIReport.xlsx`, такой же, как у ParamChecker: лист «Сводка» с полнотой и заполненностью по правилам и параметрам и по листу на каждое правило.
- В **Проверка LOI → История** у модели — полнота, заполненность, итоги по правилам и путь к отчёту.
- Модель, которой не нашлось профиля, не проверяется: запуск помечается предупреждением со списком таких моделей и причиной — «разделу «…» в расписании не назначен профиль LOI» или «раздел не распознан по имени, а профиля для остальных моделей в расписании нет».

> [!NOTE]
> Базу для дашбордов одновременно дописывают несколько Revit, в том числе на разных машинах. Чтобы они не передрались, запись идёт по очереди, через файл-замок `<база>.xlsx.lock` рядом. Если база открыта в Excel у кого-то из коллег, модель всё равно проверяется, а в истории помечается «с предупреждением».

После сохранения расписание само предупреждает о том, что заведомо помешает работе: для версии Revit источника нет ни одного агента, или у моделей одинаковые имена файлов и они перезапишут друг друга в папке результатов.

## Вкладка «Выгрузка для коллизий»

Есть у расписаний с задачей **«Выгрузка геометрии для коллизий»**.

| Поле | Что задаёт |
|---|---|
| **3D-вид** | Вид, элементы которого выгружаются; по умолчанию `Navisworks` |
| **Не открывать рабочие наборы со словом** | Рабочие наборы с этим словом в имени остаются закрытыми, их элементов в выгрузке нет; пусто — открываются все |
| **Прогнать утверждённые части после выгрузки** | Утверждённые проверки, которые прогоняются, когда закончатся все задания запуска |

Задания этой задачи берут только агенты 2.0.0 и новее. Подробно — [Коллизии](Clash#выгрузка-моделей).

## Вкладка «История изменений»

Кто и когда менял расписание и что именно поменялось: папку, модели, время, параметры задачи и так далее. Очень помогает в разговорах, которые начинаются со слов «я ничего не трогал».

## Запуск вручную

Кнопка **«Запустить сейчас»** создаёт запуск сразу, не дожидаясь времени по расписанию. В истории такой запуск помечен именем того, кто его запустил.

## Версии Revit

Модель всегда открывается в Revit той версии, в которой она сохранена, и не обновляется. Для Revit Server версия задана в источнике; для сетевой папки агент читает её из каждого файла. Если ни на одном агенте нет нужной версии, модель ждёт в очереди с пометкой **«ждёт Revit 20NN»** — см. [Частые проблемы → Модели](Troubleshooting#модели).
