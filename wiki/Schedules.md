# Расписания

Расписание отвечает на вопросы: **какую задачу** выполнить, **над какими моделями**, **куда** положить результат и **как часто**. Задач две: **выгрузка RVT / NWC** и **проверка LOI** — заполнение параметров по профилю ParamChecker. Список расписаний показывает следующий запуск, автора и того, кто менял расписание последним; расписания проверки помечены **LOI**.

Создавать и менять расписания могут операторы и администраторы.

## Вкладка «Настройка»

| Поле | Что задаёт |
|---|---|
| **Название** | Имя в списке и в истории; подставляется в папку результатов как `{расписание}` |
| **Задача** | **Выгрузка RVT / NWC** или **Проверка LOI**. От неё зависят вкладка параметров и колонки на вкладке «Модели» |
| **Источник** | Revit Server или сетевая папка из **Настройки → Источники** |
| **Папка результатов** | Куда класть RVT и NWC или отчёты LOI. Подстановки: `{расписание}`, `{дата}` (ГГГГ-ММ-ДД), `{время}` (ЧЧ-ММ) — по часовому поясу из **Настройки → Общие**. Пример: `\\nas\Выгрузки\{расписание}\{дата}`. Пользователь агента должен иметь право записи в эту папку |
| **Когда** | **По дням недели** в заданное время, **каждые N часов** начиная с заданного времени или **один раз** |
| **Приоритет** | Низкий, обычный или высокий — кто первым получает свободный Revit |
| **Таймаут на модель, мин** | Дольше этого модель не обрабатывается: Revit убивается, модель считается упавшей |
| **Повторять упавшие** | Сколько раз повторить модель, если упал или завис Revit либо пропала связь с агентом. Ошибки самой модели (нет 3D-вида, модель повреждена) не повторяются |

Выключенное расписание не запускается по времени, но его можно запустить вручную.

## Вкладка «Модели»

Дерево источника. Галочка на папке отмечает всё её содержимое. У выгрузки для каждой отмеченной модели и папки выбирается **RVT** и/или **NWC**; у проверки LOI форматов нет.

Флажок **«Добавлять новые модели из отмеченных папок автоматически»**: при каждом запуске папка разворачивается заново, и модели, появившиеся в ней позже, тоже обрабатываются. Без флажка обрабатывается только то, что было в папке при сохранении.

## Вкладка «Параметры RVT / NWC»

Для выгрузки: пресет выгрузки и переопределения его параметров только для этого расписания.

> [!NOTE]
> Модель с NWC берёт только агент, у которого для её версии Revit установлен Navisworks Exporter. Если такого агента нет, модель ждёт в очереди.

## Вкладка «Проверка LOI»

Есть у расписаний с задачей **«Проверка LOI»**. Здесь задаётся, каким профилем проверять каждую модель и что делать с итогами. Как проверка устроена целиком — [Проверка LOI: как всё устроено](LOI).

### Профиль проверки

Поле **«Профиль проверки»** — главный выбор:

| Вариант | Как работает | Когда подходит |
|---|---|---|
| **Один профиль** (разделы списка «Один на всё расписание — <группа>») | Все модели расписания проверяются этим профилем | В расписании модели одного раздела или у компании один профиль на всё |
| **По разделу модели** (группа «Для каждой модели») | Каждая модель получает профиль своего раздела из таблицы «Профили разделов проекта» | Одно расписание на весь проект, у разделов разные профили |

Во всех списках выбора профили сгруппированы по [группам профилей](LOI-profiles#группы-профилей) и подписаны с группой — «Полковая · ОВ»; в списке можно искать, начав вводить группу или имя. Профиль, которому чего-то не хватает, помечен в списке «(не готов)», а под полем красным написано, чего именно. Расписание с неготовым профилем не сохраняется — допишите профиль в **Настройки → Профили LOI** ([Профили LOI](LOI-profiles#готов-или-не-готов)).

### Профили разделов проекта

Появляется при варианте **«По разделу модели»**.

- **«+ Раздел»** добавляет строку: слева раздел (например «ОВ»), справа его профиль. Поле раздела подсказывает разделы из [справочника именования](Model-naming) и из уже проверенных моделей.
- Раздел модели ToadFlow берёт из её имени по справочнику; если для модели есть ручная поправка — из поправки.
- Раздел в таблице и раздел из справочника сравниваются **без учёта регистра, но буква в букву**: «ОВ» и «OV» (латиница) — разные разделы.
- Один раздел нельзя назначить дважды.
- **«Скопировать из расписания…»** (справа над таблицей) берёт таблицу разделов и профиль для остальных моделей из другого расписания LOI. Удобно для похожих проектов: скопировать и поправить отличия.

**Остальные модели** — что делать с моделями, раздел которых не распознан или не назначен в таблице: проверять выбранным профилем или **пропускать — с пометкой в истории запуска**.

### Исключения

Модели, которым нужен свой профиль, — что бы ни говорил раздел или профиль расписания. Работают при обоих вариантах.

- **«+ Исключение»**, слева имя модели (без папок и расширения, регистр не важен; поле подсказывает отмеченные модели), справа профиль.
- Одной модели нельзя задать два исключения.

### Профили моделей

Таблица-предпросмотр: какой профиль получит каждая модель **с текущими, ещё не сохранёнными** настройками.

| Пометка в колонке «Почему» | Значит |
|---|---|
| **исключение** | Профиль задан исключением для этой модели |
| **профиль расписания** | Выбран один профиль на всё расписание |
| **по разделу** | Раздел распознан и назначен в таблице разделов |
| **для остальных** | Раздел не распознан или не назначен, модель проверяется профилем остальных моделей |
| **пропускается** | Профиля нет — модель не будет проверена |

Порядок выбора профиля: исключение → один профиль расписания → профиль раздела → профиль остальных моделей → пропуск.

В таблице — модели, отмеченные на вкладке «Модели» по одной. Модели из отмеченных папок появляются после первого запуска расписания.

### Что и как проверять

| Поле | Что задаёт |
|---|---|
| **Вид: своё для расписания** | Без флажка — вид из профиля каждой модели. С флажком — своё имя вида, с которого собираются элементы; пустое поле — вся модель |
| **Не открывать РН, содержащие: своё для расписания** | Без флажка — как в профиле. С флажком — своё слово: рабочие наборы с ним в имени остаются закрытыми, их элементы не проверяются |
| **Не загружать связи** | Модель копируется во временную папку агента, в копии связи не загружаются — открытие быстрее. Включено по умолчанию |
| **В листах правил только элементы с пропусками** | Итоги считаются по всем элементам, а в листы правил попадают только элементы с незаполненными параметрами — отчёты по большим моделям в разы меньше |
| **Записывать итоги в аналитику ToadFlow** | Итоги попадают на страницу [Аналитика LOI](Analytics). Включено по умолчанию; не действует, если аналитика выключена в **Настройки → Аналитика LOI** |
| **База для дашбордов** | Путь к книге Excel (`.xlsx`), куда каждая проверенная модель дописывает итоги — та же база, что ведёт ParamChecker, для Power BI. Подстановки — как у папки результатов: `{расписание}`, `{дата}`, `{время}`. Пусто — база не ведётся |

### Что получается после запуска

- На каждую модель в папке результатов — отчёт `<модель>_LOIReport.xlsx`, такой же, как у ParamChecker: лист «Сводка» с полнотой и заполненностью по правилам и параметрам и по листу на каждое правило.
- В **Истории** у модели — полнота, заполненность, итоги по правилам и путь к отчёту.
- Модель, которой не нашлось профиля, не проверяется: запуск помечается предупреждением со списком таких моделей и причиной — «разделу «…» в расписании не назначен профиль LOI» или «раздел не распознан по имени, а профиля для остальных моделей в расписании нет».

> [!NOTE]
> Базу для дашбордов одновременно дописывают несколько Revit, в том числе на разных машинах: запись идёт по очереди, через файл-замок `<база>.xlsx.lock` рядом. Если база открыта в Excel, модель всё равно проверяется, а в истории она помечается «с предупреждением».

После сохранения расписание предупреждает о том, что заведомо помешает работе: для версии Revit источника нет ни одного агента, или у моделей одинаковые имена файлов и они перезапишут друг друга в папке результатов.

## Вкладка «История изменений»

Кто и когда менял расписание и что именно поменялось: папку, модели, время, параметры задачи и так далее.

## Запуск вручную

Кнопка **«Запустить сейчас»** создаёт запуск сразу, не дожидаясь времени по расписанию. В истории такой запуск помечен именем того, кто его запустил.

## Версии Revit

Модель всегда открывается в Revit той версии, в которой она сохранена, и не обновляется. Для Revit Server версия задана в источнике; для сетевой папки агент читает её из каждого файла. Если ни на одном агенте нет нужной версии, модель ждёт в очереди с пометкой **«ждёт Revit 20NN»**.
