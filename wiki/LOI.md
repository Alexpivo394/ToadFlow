# Проверка LOI: как всё устроено

**LOI** (level of information) — насколько заполнены параметры элементов модели. ToadFlow по расписанию открывает модели в Revit на агентах, проверяет их по правилам ParamChecker и сохраняет итоги:

- **отчёт Excel на каждую модель** — какие элементы и какие параметры не заполнены;
- **книгу Excel для Power BI** (база для дашбордов), если она указана в расписании;
- **аналитику в ToadFlow** — графики по объектам, разделам и моделям во времени.

Эта страница описывает, из каких частей состоит проверка, как они связаны и что настраивать в каком порядке. Подробности по каждой части — на отдельных страницах:

| Страница | О чём |
|---|---|
| [Профили LOI](LOI-profiles) | Правила проверки: какие элементы отбирать и какие параметры у них должны быть заполнены |
| [Разбор имён моделей](Model-naming) | Как из имени модели получить объект, раздел и часть здания. Нужен для аналитики и для выбора профиля по разделу |
| [Расписания → вкладка «Проверка LOI»](Schedules#вкладка-проверка-loi) | Какие модели проверять, каким профилем, когда и куда класть отчёты |
| [Аналитика LOI](Analytics) | Страница с графиками и таблицами, ручные проверки из ParamChecker, Power BI |

## Из чего состоит проверка

| Часть | Где находится | Зачем | Обязательна? |
|---|---|---|---|
| **Профиль LOI** | Настройки → Профили LOI | Правила: какие элементы отобрать и какие параметры у них проверить | **Да**, нужен хотя бы один готовый профиль |
| **Каталог Revit** | Настройки → Профили LOI, блок внизу | Подписи категорий и подсказки имён параметров в редакторе правил | Нет. Без каталога редактор работает, только неудобнее |
| **Расписание проверки** | Расписания → Новое расписание, задача «Проверка LOI» | Какие модели, когда, каким профилем, куда класть отчёты | **Да** |
| **Справочник именования** | Настройки → Аналитика LOI, блок «Разбор имён моделей» | Объект, раздел и часть здания из имени модели | Только если профиль выбирается **по разделу модели** или нужны разрезы в аналитике |
| **Ручные поправки моделей** | Настройки → Аналитика LOI, блок внизу | Задать объект или раздел модели, имя которой справочник не разбирает | Нет |
| **Аналитика** | Главное меню → Аналитика LOI | Графики и таблицы по итогам проверок | Нет. Включена по умолчанию |
| **База для дашбордов** | Поле в расписании | Книга Excel с итогами для Power BI, как у ParamChecker | Нет |

> [!IMPORTANT]
> В интерфейсе два пункта «Аналитика LOI»: в **главном меню** — страница с графиками, а в **Настройках** — включение аналитики, справочник именования моделей и ручные поправки. Их легко перепутать.

## Как проходит одна проверка

```
Расписание запускается (по времени или кнопкой «Запустить сейчас»)
   │
   ▼
Для каждой модели сервер выбирает профиль:
   исключение для модели → один профиль расписания → профиль раздела → профиль остальных моделей
   │                                                   ▲
   │                                   раздел — из имени модели по справочнику
   │                                   (ручная поправка главнее справочника)
   │
   │   профиль не нашёлся → модель пропускается, в истории запуска — предупреждение
   ▼
Агент открывает модель в Revit её версии: копия во временной папке,
связи не загружены, рабочие наборы с ключевым словом закрыты
   │
   ▼
Revit собирает элементы с вида (или со всей модели), отбирает их правилами
и смотрит, заполнены ли проверяемые параметры
   │
   ├──► <модель>_LOIReport.xlsx в папке результатов расписания
   ├──► строка в базе для дашбордов (.xlsx), если она указана
   └──► итоги на сервер ──► аналитика ToadFlow (объект, раздел, часть — по справочнику)
```

Исходная модель не меняется и не сохраняется: агент работает с копией и закрывает её без сохранения.

## Какой вариант выбрать

### Вариант 1. Один профиль на всё расписание

Самый простой. В расписании выбирается один профиль, и им проверяются все отмеченные модели.

- Подходит, если в расписании модели одного раздела (например, только АР) или у компании один общий профиль на все разделы.
- Для проверки справочник именования **не нужен**. Он понадобится только для разрезов «объект» и «раздел» на странице аналитики.
- Разным разделам нужны разные профили? Тогда заведите по расписанию на раздел или используйте вариант 2.

### Вариант 2. Профиль по разделу модели

Одно расписание охватывает весь проект, а каждая модель получает профиль своего раздела: модели ОВ проверяются профилем ОВ, модели АР — профилем АР.

- Раздел модели ToadFlow узнаёт из её имени по [справочнику именования](Model-naming). Коды разделов по ГОСТ латиницей (`AR`, `OV`, `VK`, `EOM`…) в нём уже есть.
- Таблица «раздел → профиль» задаётся в каждом расписании отдельно: в разных проектах у одного раздела могут быть разные профили. Таблицу можно скопировать из расписания похожего проекта.
- Модели, раздел которых не распознан или которому не назначен профиль, проверяются профилем «для остальных моделей» или пропускаются.
- Отдельной модели можно назначить свой профиль исключением.

### Вариант 3. Только аналитика по ручным проверкам

Проектировщики проверяют модели сами в плагине ParamChecker, а итоги уходят в ToadFlow по личному токену. Расписания и агенты для этого не нужны — см. [Аналитика LOI → Ручные проверки из ParamChecker](Analytics#ручные-проверки-из-paramchecker).

## Настройка с нуля по шагам

Нужен работающий сервер и хотя бы один агент в сети с Revit нужной версии — см. [Первый запуск](Getting-started).

### Шаг 1. Профиль

**Настройки → Профили LOI.**

- Профили уже есть в ParamChecker — нажмите **«Загрузить из ParamChecker»** и выберите файл профилей из плагина.
- Профилей нет — **«+ Новый профиль»**, затем правила: что отбирать и какие параметры проверять.
- Профили раскладывайте по **группам** — обычно по проектам. Внутри группы имена уникальны, так что «ОВ» может быть в каждом проекте, а профиль для нового проекта удобно получить кнопкой **«Копировать»**.

Профиль должен быть помечен зелёным **«готов»**. Если он **«не готов»**, наведите курсор на пометку: там написано, чего не хватает. Подробно — [Профили LOI](LOI-profiles).

### Шаг 2. Каталог Revit (рекомендуется)

Там же, в блоке **«Каталог Revit для редактора правил»** — кнопка **«Обновить из Revit»**. Свободный Revit на агенте снимет список категорий и параметров. Через пару минут в редакторе правил появятся русские названия категорий и подсказки имён параметров, а имена с опечатками будут подсвечены.

### Шаг 3. Справочник именования (для варианта 2 и для аналитики)

**Настройки → Аналитика LOI → блок «Разбор имён моделей».**

1. Если стандартные записи или шаблоны удалялись, верните их: **«Стандартный справочник» → «Добавить недостающие стандартные записи и шаблоны»**.
2. Внизу блока, в **«Предпросмотре»**, нажмите **«Модели сервиса»**, затем **«Разобрать»**. Таблица покажет, как ToadFlow понимает имена ваших моделей.
3. Красный прочерк в колонке «Объект» или «Раздел» — поле не распознано. Оранжевые куски в колонке «Не распознано» — части имени, которых нет в справочнике.
4. Щёлкните оранжевый кусок и укажите, что он означает: объект, раздел, часть здания или «Пропустить». Повторите для всех кусков.
5. Нажмите **«Сохранить справочник»**.

Подробно, с примерами — [Разбор имён моделей](Model-naming).

> [!WARNING]
> Для варианта 2 раздел в справочнике и раздел в таблице расписания должны называться **одинаково**: если справочник выдаёт «ОВ», то и в расписании должно быть «ОВ», а не «OV» и не «Отопление». Регистр не важен.

### Шаг 4. Расписание

**Расписания → Новое расписание**, задача **«Проверка LOI»**.

1. **Настройка:** название, источник, папка для отчётов, когда запускать.
2. **Модели:** отметьте модели или папки целиком.
3. **Проверка LOI:**
   - вариант 1 — в поле **«Профиль проверки»** выберите профиль;
   - вариант 2 — выберите **«По разделу модели»**, нажмите **«+ Раздел»**, укажите раздел и его профиль; повторите для каждого раздела проекта; решите, что делать с остальными моделями.
4. Посмотрите таблицу **«Профили моделей»**: какой профиль получит каждая модель и почему. Строки «пропускается» означают, что модель не будет проверена.
5. **Сохранить.**

Подробно — [Расписания → вкладка «Проверка LOI»](Schedules#вкладка-проверка-loi).

### Шаг 5. Первый запуск

Нажмите **«Запустить сейчас»** и откройте **История и логи**. У каждой модели видны полнота, заполненность и путь к отчёту, в раскрытой строке — итоги по каждому правилу. Если модель пропущена, в предупреждении запуска написано почему.

### Шаг 6. Аналитика

Откройте **Аналитика LOI** в главном меню. Итоги появляются сразу после проверки каждой модели. Если объекты или разделы показаны как «не распознано», дополните справочник (шаг 3) и нажмите **«Пересчитать аналитику по справочнику»** в **Настройки → Аналитика LOI**: уже записанные проверки разложатся заново.

## Минимум, без которого проверка не работает

- [ ] Агент в сети, у него есть Revit версии моделей, лимит экземпляров этой версии больше нуля.
- [ ] Агент версии 1.1.0 или новее: старые агенты проверку LOI не выполняют.
- [ ] Хотя бы один профиль с пометкой «готов».
- [ ] Расписание с задачей «Проверка LOI», отмеченными моделями и папкой результатов, в которую пользователь агента может писать.
- [ ] В расписании выбран профиль; в варианте 2 — назначены профили разделам или выбран профиль для остальных моделей.

Всё остальное — каталог, справочник, поправки, база для дашбордов — улучшает результат, но для запуска не нужно.

## Где смотреть результат

| Что | Где |
|---|---|
| Итог каждой модели, причина пропуска, пошаговый лог | **История и логи** → запуск → модель |
| Какие элементы не заполнены | Отчёт `<модель>_LOIReport.xlsx` в папке результатов: лист «Сводка» и по листу на правило |
| Динамика по объектам, разделам, моделям | **Аналитика LOI** в главном меню |
| Свои отчёты в Power BI | База для дашбордов (Excel) или представления `loi_analytics` и `loi_analytics_fields` в базе сервера — см. [Аналитика LOI → Power BI](Analytics#power-bi) |
