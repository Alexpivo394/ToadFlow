# Профили LOI

**Настройки → Профили LOI.** Профиль — набор правил проверки: какие элементы модели отобрать и какие параметры у них должны быть заполнены. Это те же профили, что в плагине ParamChecker: файл из плагина загружается в ToadFlow как есть, а профиль из ToadFlow скачивается файлом, который плагин импортирует обратно.

Смотреть профили могут все пользователи. Создавать, менять, загружать и удалять — операторы и администраторы.

Как профиль участвует в проверке целиком — см. [Проверка LOI: как всё устроено](LOI).

## Группы профилей

Когда у каждого проекта свои профили разделов, профилей становится много. Поэтому профили раскладываются по **группам** — обычно группа это проект: «Полковая», «Донской».

- **Имя уникально внутри группы.** В каждой группе может быть свой профиль «ОВ», «АР», «ВК» — не нужно придумывать «ОВ Полковая», «ОВ Донской».
- **В отчёт, аналитику и списки выбора профиль попадает с группой:** «Полковая · ОВ». Так профили «ОВ» разных проектов не путаются.
- **Группа необязательна.** Профили без группы собраны в разделе «Без группы» в конце списка — например, общие профили компании.
- Группа задаётся в редакторе профиля (поле **«Группа»** подсказывает существующие группы) или при загрузке файла из ParamChecker.
- **Переименовать группу** (кнопка в раскрытой группе) — переименовывает группу у всех её профилей, например когда переименовали проект. Если ввести имя существующей группы, профили переедут в неё; если там уже есть профили с такими же именами, ToadFlow откажет и перечислит их.
- **Копировать** у профиля — открывает копию в редакторе. Удобно, чтобы завести профиль раздела для нового проекта: скопировать «Полковая · ОВ», сменить группу на «Донской», поправить правила и сохранить.

> [!TIP]
> Типовой порядок для нового проекта: в группе похожего проекта нажмите **«Копировать»** у каждого нужного профиля, поменяйте группу на новый проект и сохраните. Затем в расписании нового проекта назначьте эти профили разделам (или скопируйте таблицу разделов из расписания похожего проекта и замените профили).

Если профили были заведены до появления групп, все они лежат в «Без группы». Чтобы разложить их, откройте профиль, укажите группу и, если нужно, укоротите имя («ОВ Полковая» → группа «Полковая», имя «ОВ»).

## Список профилей

Профили показаны по группам. Пока групп три или меньше, все раскрыты; когда групп больше — свёрнуты, чтобы был виден их список. Рядом с именем группы — сколько в ней профилей и сколько из них **не готово**. Когда профилей больше пяти, сверху появляется поиск по группе и имени — он раскрывает группы с найденными профилями.

| Колонка | Что показывает |
|---|---|
| Название | Имя профиля внутри группы |
| Правил | Сколько правил в профиле; если задан вид по умолчанию — его имя |
| **готов** / **не готов** | Можно ли проверять этим профилем. Наведите курсор на «не готов» — появится список того, чего не хватает |
| Кто и когда менял | Последнее изменение |

Щелчок по строке открывает редактор профиля под списком.

| Кнопка | Что делает |
|---|---|
| **Загрузить из ParamChecker** | Добавляет профили из файла плагина — см. [ниже](#загрузка-из-paramchecker) |
| **+ Новый профиль** | Пустой профиль с одним правилом, без группы |
| **+ Профиль в группу**, **Загрузить в группу** | То же, но сразу в раскрытую группу |
| **Переименовать группу** | Новое имя группы для всех её профилей — см. [Группы профилей](#группы-профилей) |
| **Скачать** | Файл `<профиль>.json` с этим профилем — его можно импортировать в ParamChecker. Группа в файл не попадает |
| **Копировать** | Копия профиля в редакторе — сохраняется отдельным профилем |
| **Удалить** | Удаляет профиль. Профиль, который выбран хотя бы в одном расписании (одним профилем, у раздела, для остальных моделей или в исключении), удалить нельзя — сначала поменяйте его в расписаниях |

## Загрузка из ParamChecker

Подойдёт файл экспорта профилей из ParamChecker или его файл `profiles.json`, в том числе от старых версий плагина.

- В окне загрузки укажите **группу** — все профили файла лягут в неё. Пусто — без группы.
- В файле может быть несколько профилей — загрузятся все.
- Профили **добавляются** к имеющимся. Если в этой группе профиль с таким именем уже есть, новый получит номер: «АР (2)». Ничего не перезаписывается.
- Переносятся правила, вид по умолчанию и ключевое слово рабочих наборов. **Модели из файла не переносятся**: в ToadFlow модели задаёт расписание.
- В старых версиях ParamChecker категории записаны числами. ToadFlow переводит их в категории Revit; числа, которых он не знает, не переносятся, и после загрузки появится предупреждение со списком.

После загрузки откройте каждый профиль и проверьте, что он **«готов»**.

## Редактор профиля

### Поля профиля

| Поле | Что задаёт |
|---|---|
| **Группа** | Обычно проект. Пусто — без группы. Подсказывает существующие группы |
| **Название** | Обязательное, уникальное внутри группы, например «ОВ» |
| **Вид по умолчанию** | Имя вида, с которого собираются элементы. Пусто — проверяется вся модель. Регистр не важен; если видов с таким именем несколько, берётся 3D-вид. Расписание может задать свой вид |
| **Не открывать РН, содержащие** | Рабочие наборы, в имени которых есть это слово, при открытии остаются закрытыми, их элементы не проверяются. Пусто — открываются все. Расписание может задать своё слово |

> [!NOTE]
> Если указан вид, проверяются элементы, **видимые на этом виде**: скрытые фильтрами, подрезкой или рабочими наборами в проверку не попадут. Помещения, пространства и зоны на 3D-видах не видны, поэтому их ToadFlow всегда берёт из всей модели, кроме неразмещённых (с нулевой площадью).

Если в модели нет вида с указанным именем, модель не проверяется, а в истории появляется ошибка со списком 3D-видов модели.

### Правила

В профиле одно или несколько правил. Каждое правило проверяется отдельно и в отчёте получает свой лист. Кнопки справа от названия правила: **выше**, **ниже**, **дублировать**, **удалить**.

| Поле правила | Что задаёт |
|---|---|
| **Название** | Имя правила и листа в отчёте, например «Стены» или «Двери наружные» |
| **Отбор элементов** | Как выбирать элементы: по категориям, по условиям или по их сочетанию — см. ниже |
| **Условия верхнего уровня** | Если в отборе участвуют условия: **Все условия (И)** или **Любое условие (ИЛИ)** |
| **Категории** | Категории Revit, из которых берутся элементы. Начните вводить название — список подскажет |
| **Условия на параметры** | Параметр, оператор и значение — см. [Условия](#условия) |
| **Проверяемые параметры** | Параметры, которые должны быть заполнены у отобранных элементов |

### Отбор элементов

| Режим | Какие элементы попадают в правило | Пример |
|---|---|---|
| **Только категории** | Все элементы выбранных категорий | Категория «Стены» — все стены |
| **Только условия** | Элементы любых категорий, которые подходят под условия | `ADSK_Код изделия` заполнен — всё, у чего есть код |
| **Категории И условия** | Элементы выбранных категорий, которые подходят под условия | «Двери» и `Функция` равно `Наружные` — только наружные двери |
| **Категории ИЛИ условия** | Элементы выбранных категорий, а также элементы любых категорий, которые подходят под условия | «Оборудование» или `ADSK_Наименование` содержит `насос` |

Новое правило создаётся в режиме **«Категории И условия»** без условий — это то же самое, что «Только категории»: если условий нет, подходит любой элемент выбранных категорий.

### Условия

Условие — это **параметр**, **оператор** и, если оператору нужно, **значение**. Параметр ищется и у экземпляра, и у его типа.

| Оператор | Условие выполняется, если |
|---|---|
| **Равно** / **Не равно** | Значение совпадает (не совпадает) с заданным. Регистр не важен. Если задано число, а параметр числовой, сравниваются числа: `1200` равно и `1200`, и `1200 мм` |
| **Больше**, **Больше или равно**, **Меньше**, **Меньше или равно** | Сравниваются числа в **единицах проекта**. Если параметр или значение — не число, условие не выполняется |
| **Содержит** / **Не содержит** | Текст параметра содержит (не содержит) заданный текст, без учёта регистра |
| **Начинается с** / **Заканчивается на** | Текст параметра начинается (заканчивается) заданным текстом, без учёта регистра |
| **Параметр есть** / **Параметра нет** | У элемента или его типа такой параметр есть (нет), заполнен он или нет — не важно |
| **Заполнен** / **Не заполнен** | Параметр есть и у него непустое значение (параметра нет или значение пустое) |

Как условия складываются вместе:

- Условия верхнего уровня связываются так, как выбрано в **«Условия верхнего уровня»**: все сразу (И) или хотя бы одно (ИЛИ).
- **Группа (И)** — несколько условий, которые должны выполниться все вместе. Группа считается одним условием верхнего уровня. Так собираются выражения вида «(А и Б) или В»: логика верхнего уровня — ИЛИ, условия А и Б — в группе, В — отдельно. Группа внутри группы не создаётся.
- Недописанное условие (без параметра) и пустая группа не учитываются.

### Проверяемые параметры

Для каждого отобранного элемента и каждого проверяемого параметра результат один из трёх:

| Результат | Когда | В отчёте |
|---|---|---|
| **Заполнен** | Параметр есть у экземпляра или типа, и у него непустое значение | Значение |
| **Пусто** | Параметр есть, но значение пустое | Пустая ячейка |
| **Нет параметра** | У элемента и его типа такого параметра нет | Пометка «нет параметра» |

> [!NOTE]
> Значение считается заполненным, если Revit показывает его непустым. Число `0` и «Нет» у параметра «Да/Нет» — тоже заполненные значения.

Параметры вводятся по одному (имя и Enter), через запятую или точку с запятой. Список можно скопировать из столбца Excel и вставить целиком — каждая строка станет параметром. Повторы убираются сами.

Если каталог Revit снят с подключённым ФОП, имена, которых в каталоге нет, подсвечиваются под полем: **«Нет в каталоге — возможно, опечатка»**. Это подсказка, а не ошибка: параметр семейства, которого нет в ФОП, тоже попадёт в подсветку.

## Готов или не готов

Профиль **«не готов»**, если хотя бы в одном правиле:

- не выбраны параметры для проверки;
- в режиме «Только категории» или «Категории И условия» не выбраны категории;
- в режиме «Только условия» нет ни одного дописанного условия;
- в режиме «Категории ИЛИ условия» нет ни категорий, ни условий.

Неготовый профиль можно сохранить и доделать позже. В редакторе под каждым правилом красным написано, чего ему не хватает. Расписание с неготовым профилем не сохраняется, а если профиль сломали после сохранения расписания, его модели пропускаются с пометкой «профиль не готов к запуску».

## Как считаются итоги

Пример: правило «Стены» отобрало 4 стены, проверяемые параметры — `ADSK_Марка` и `ADSK_Материал`.

| Стена | ADSK_Марка | ADSK_Материал |
|---|---|---|
| 1 | заполнен | заполнен |
| 2 | заполнен | пусто |
| 3 | пусто | нет параметра |
| 4 | заполнен | заполнен |

- **Заполненность** — доля заполненных значений среди всех проверенных: 5 заполненных из 8 (4 стены × 2 параметра) = **62,5 %**. «Пусто» и «нет параметра» одинаково считаются незаполненными.
- **Полнота** — доля элементов, у которых заполнено **всё**: стены 1 и 4, то есть 2 из 4 = **50 %**.

Итоги модели складываются из всех её правил: заполненные значения и элементы суммируются по правилам.

## Примеры правил

**Стены: марка и материал.** Отбор — «Только категории», категории — «Стены», параметры — `ADSK_Марка`, `ADSK_Материал`.

**Только наружные двери.** Отбор — «Категории И условия», категории — «Двери», условие — `Функция` **Равно** `Наружные`, параметры — `ADSK_Марка`, `Огнестойкость`.

**Всё, что идёт в спецификацию.** Отбор — «Только условия», условие — `ADSK_Наименование` **Заполнен**, параметры — `ADSK_Код изделия`, `ADSK_Завод-изготовитель`, `ADSK_Единица измерения`.

**Трубы больших диаметров или любые элементы с меткой.** Отбор — «Категории ИЛИ условия», категории — «Трубы»; условия, логика ИЛИ: группа (`Диаметр` **Больше или равно** `100`), условие `Комментарии` **Содержит** `проверить`.

## Каталог Revit

У сервера ToadFlow нет своего Revit, поэтому названия категорий и имена параметров для редактора снимает Revit на агенте. Блок **«Каталог Revit для редактора правил»** — внизу страницы.

- **Обновить из Revit** (операторы и администраторы) ставит в очередь задание. Свободный Revit на агенте создаёт пустой проект и читает из него категории, системные параметры и параметры из файла общих параметров (ФОП), подключённого в этом Revit. Обычно это занимает пару минут; ход виден в **Истории** как запуск «Каталог категорий и параметров Revit 20NN».
- Если у агентов несколько версий Revit, рядом с кнопкой появится выбор версии. Каталог хранится для каждой версии отдельно.
- Пометка **«без ФОП»** — у Revit на агенте не подключён ФОП. Тогда ADSK-параметров в подсказках нет и опечатки не подсвечиваются. Подключите ФОП в Revit на машине агента (под пользователем агента) и обновите каталог.
- Без каталога редактор тоже работает: категории показываются ключами вроде `OST_Walls`, а имена параметров вводятся без подсказок.

Категории, которых нет в каталоге (например, из другой версии Revit), в правиле не теряются: они показаны в группе «Нет в каталоге» под своими ключами.

## Частые вопросы

**Профиль поменяли — что будет с прошлыми проверками?** Ничего: они остались с прежними итогами. В аналитике изменение заполненности между проверками с разными правилами помечается звёздочкой `*` — рост или падение может объясняться правилами, а не моделью.

**Можно ли переименовать профиль или перенести его в другую группу?** Да. Расписания ссылаются на профиль, а не на имя, поэтому ничего не сломается. В аналитике старые проверки останутся под старым именем, новые запишутся под новым («Группа · Имя»).

**Чем отличается профиль ToadFlow от профиля ParamChecker?** Ничем, кроме моделей и группы: в ToadFlow у профиля нет списка моделей (их задаёт расписание), зато есть группа.
