# Словарь

У ToadFlow свой язык. «Слепок», «кусок», «прогон», «ферма» — звучит как заметки сельского кузнеца, но за каждым словом стоит точный смысл. Здесь они все, по алфавиту.

Не нашли слово? Попробуйте Ctrl+F — возможно, оно в другом разделе.

**Разделы:** [общее](#общее) · [проверка LOI и имена моделей](#проверка-loi-и-имена-моделей) · [коллизии](#коллизии) · [семейства](#семейства)

## Общее

| Термин | Что значит |
|---|---|
| **Агент** | Программа ToadFlow на Windows-машине с Revit. Получает задания от сервера, запускает Revit и следит за ним. См. [Установка агента](Agent) |
| **Аддин** | Надстройка ToadFlow в Revit. Работает только в Revit, который запустил агент |
| **Журнал действий** | Кто и когда что менял: расписания, пользователи, настройки, агенты, ручные запуски. **Администрирование → Журнал действий** |
| **Задание** | Обработка одной модели в одном запуске: выгрузка или проверка |
| **Запуск** | Одно срабатывание расписания: по времени, вручную или повтор упавших. Состоит из заданий — по одному на модель |
| **Источник** | Откуда расписание берёт модели: Revit Server или сетевая папка |
| **Координатор** | Роль, которая управляет работой: расписания, проверки коллизий, заявки, разделы пользователей. В API — `Operator` |
| **Модуль** | Часть ToadFlow со своими заданиями и страницами: выгрузка, проверка LOI, коллизии, семейства. Набор модулей задаётся при установке строкой `MODULES` в `.env`; выключенного модуля нет ни в меню, ни в API, его данные сохраняются |
| **Папка результатов** | Куда расписание кладёт RVT, NWC или отчёты LOI |
| **Пресет выгрузки** | Именованный набор параметров RVT и NWC |
| **Проектировщик** | Роль с собственным узким рабочим местом: свои коллизии, каталог семейств и заявки. См. [Проектировщику](Designer) |
| **Пространство** | Пункт узкой полосы слева: «Обзор», модуль, «Ферма» или «Администрирование». У пространства своё меню страниц |
| **Токен ToadTools** | Личный токен компьютера, который ToadTools получает при входе в окне «Подключение к ToadFlow». С ним панели «Коллизии», «Семейства» и ParamChecker работают от имени пользователя |
| **Требует внимания** | Главный блок «Обзора»: что нужно сделать или починить — агент не в сети, заявки, ошибки за сутки, мало места, рабочий процесс модуля молчит |
| **Ферма** | Все машины с Revit и агентом вместе. А ещё — пространство с общим для всех модулей: агенты, очередь и журнал всех заданий, источники моделей, именование моделей |
| **Экземпляр Revit** | Один запущенный агентом Revit. Сколько их одновременно на машине, задают лимиты агента |

## Проверка LOI и имена моделей

| Термин | Что значит |
|---|---|
| **LOI** | Level of information — уровень информационного наполнения: насколько заполнены параметры элементов |
| **Аналитика LOI** | Страница с графиками заполненности по объектам, разделам и моделям: **Проверка LOI → Аналитика**. См. [Аналитика LOI](Analytics). Включение аналитики и срок хранения — на другой странице, **Проверка LOI → Настройка аналитики** |
| **База для дашбордов** | Книга Excel, куда каждая проверенная модель дописывает свои итоги — для Power BI. Задаётся в расписании LOI |
| **Группа профилей** | Папка для профилей LOI, обычно проект. Имя профиля уникально внутри группы; в отчётах профиль подписан «Группа · Имя» |
| **Заполненность** | Доля заполненных значений среди всех проверенных (элементы × параметры). Отвечает на вопрос «сколько работы сделано» |
| **Исключение** | В расписании LOI — свой профиль для конкретной модели, главнее раздела и профиля расписания |
| **Каталог Revit** | Список категорий и параметров, снятый в Revit на агенте. Нужен редактору правил для подписей и подсказок |
| **Кусок имени** | Часть имени модели между разделителями: в `SEV_K2_OV` куски `SEV`, `K2`, `OV` |
| **Нет параметра** | У элемента и его типа нет проверяемого параметра. Считается незаполненным значением. Вопрос к автору семейства |
| **Остальные модели** | В расписании «по разделу модели» — модели, раздел которых не распознан или не назначен. Проверяются отдельным профилем или пропускаются |
| **Полнота** | Доля элементов, у которых заполнены все проверяемые параметры. Всегда строже заполненности |
| **Правило** | Часть профиля: какие элементы отобрать и какие параметры у них проверить. В отчёте — отдельный лист |
| **Профиль LOI** | Набор правил проверки. Тот же формат, что у плагина ParamChecker. См. [Профили LOI](LOI-profiles) |
| **Пусто** | Параметр у элемента есть, но значение не заполнено. Вопрос к проектировщику |
| **Раздел** | Раздел проекта: АР, КР, ОВ, ВК… Определяется из имени модели справочником именования |
| **Разделитель** | Символ, по которому имя модели режется на куски, обычно `_` |
| **Ручная поправка** | Объект, раздел, часть или заказчик, заданные конкретной модели вручную. Главнее справочника |
| **Свои поля** | Поля справочника именования сверх объекта, раздела и части — например «Стадия». Есть фильтры по ним в аналитике |
| **Справочник именования** | Настройки разбора имён моделей: записи, шаблоны кусков, выражения на имя целиком. Общий для всех модулей: **Ферма → Именование моделей**. См. [Разбор имён моделей](Model-naming) |
| **ФОП** | Файл общих параметров Revit. Если он подключён в Revit на агенте, каталог содержит ADSK-параметры |
| **Часть здания** | Корпус, секция, блок — то, что распознают шаблоны кусков |
| **Шаблон куска** | Регулярное выражение, которое распознаёт класс кусков имени: `K1`, `K12` → «корпус 1», «корпус 12» |

## Коллизии

| Термин | Что значит |
|---|---|
| **Группа проверки** | Строка и столбец матрицы: раздел или своя группа, например «Проезды» |
| **Допуск** | Глубина пересечения в миллиметрах, до которой пересечение не считается коллизией; по умолчанию 20 мм |
| **Коллизия** | Пара пересекающихся элементов двух моделей с постоянным номером, статусом и лентой событий |
| **Кто правит** | Сторона коллизии, которая её исправляет: раздел A, раздел B или обе стороны |
| **Матрица** | Какие пары групп проверяются и с каким допуском |
| **Набор** | Элементы группы, отобранные условиями по категории, семейству, типу, параметрам |
| **Открытые коллизии** | Статусы «новая», «активная», «вернулась», «исправлена (ждёт)» и «не проверена» |
| **Прогон** | Один поиск коллизий движком: черновика или утверждённой версии |
| **Слепок** | Полная выгрузка геометрии и параметров одной модели на сервере |
| **Утверждённая версия** | Зафиксированный черновик с номером (v1, v2…). Только её прогоны создают и меняют коллизии |
| **Часть** | Модели, которые проверяются на коллизии вместе, со своими разделами и проверкой. См. [Коллизии](Clash#части-и-черновик). Не путать с «частью здания» |
| **Черновик** | Настройка проверки части, которую можно править и прогонять, ничего не меняя в базе коллизий. Песочница |

## Семейства

| Термин | Что значит |
|---|---|
| **Агент библиотеки** | Агент, который обходит папку библиотеки, хранит копии версий в `.toadflow` и перекладывает файлы по кнопкам веба. Назначается в **Семейства → Параметры**. См. [Семейства](Families#для-администратора) |
| **Библиотека семейств** | Сетевая папка с семействами Revit. Она главная: сервер хранит только карточки с путём и хешем |
| **Версия-кандидат** | Файл в папке проверки с именем утверждённого семейства. Пока его не переложили на место, проектировщик получает прежнюю версию |
| **Заявка на семейство** | Просьба сделать семейство, которого нет в каталоге, или исправить существующее. У заявки всегда понятно, чей ход. См. [Заявки](Families#заявки) |
| **Карточка семейства** | Одна запись каталога на семейство: путь, состояние, содержимое действующей версии и история версий |
| **Метка семейства** | Запись в загруженном семействе проекта: из какой карточки и версии оно загружено. По ней панель «В проекте» отличает актуальное от устаревшего |
| **Направление BIM** | Кто делает заявки каких разделов: «ОВ/ВК», «АР/КР»… Заявка уходит координаторам своего направления. См. [Направления BIM](Families#направления-bim) |
| **Нужно решение** | Случаи, которые система не решает сама: конфликт имён, дубль, неясный перенос, нечитаемый файл, правка без проверки |
| **Обход библиотеки** | Перечень файлов папки с хешами, который агент библиотеки присылает серверу раз в интервал |
| **Папка проверки** | Папка в корне библиотеки (по умолчанию `_На проверке`); всё, что в ней, — «на проверке» |
| **Приёмка** | Этап заявки, когда семейство готово и автор должен сказать «Подходит» или «Не то…». Молчит — заявка принимается сама |
