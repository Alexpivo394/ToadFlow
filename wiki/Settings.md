# Где что настраивается

Отдельного пункта «Настройки» в ToadFlow нет. Это не забывчивость, а принцип: настройка лежит там, где ею пользуются.

- Настройка **модуля** — в самом модуле, внизу его меню, под разделителем.
- Общее для **всех модулей** — в **Ферме**.
- **Люди и сервер** — в **Администрировании**.
- **Своё** — имя, должность, контакты, пароль, уведомления — в **Профиле** (значок внизу полосы слева). Разделы пользователя задаёт координатор.

А эта страница — шпаргалка для тех, кто помнит, *что* хочет поменять, но не помнит *где*.

**Про списки.** Все списки (пользователи, расписания, история, агенты, источники, пресеты, журнал действий) устроены одинаково: сортировка щелчком по заголовку столбца (по возрастанию → по убыванию → как было), поиск и фильтры по значениям столбцов. Всё это сохраняется в адресе страницы — ссылка открывает тот же вид.

## Агенты

**Ферма → Агенты.** Машины с Revit, на которых стоит агент ToadFlow.

| Колонка | Что показывает |
|---|---|
| **Машина**, **Статус** | Имя компьютера; **в сети**, **не берёт новые**, **нет связи** или **отключён** |
| **Версия агента** | Пометка **«устарел»** — агент старше сервера, его стоит обновить |
| **Найденные Revit** | Какие версии Revit агент нашёл и есть ли для них Navisworks Exporter |
| **Экземпляров (макс.)** | Сколько Revit каждой версии агент держит одновременно; общее число на машину — сумма по версиям, ограничено только памятью машины |

Действия (меню **«Действия»** в строке агента):

- **Подключить агента** — одноразовый код для установки агента, см. [Установка агента](Agent).
- **Лимиты экземпляров** — сколько Revit каждой версии держать.
- **Не брать новые задания / Брать новые задания** — агент доделывает текущие выгрузки и не берёт новые. Нужно перед обновлением или обслуживанием машины.
- **Отключить** — агент больше не сможет подключиться к серверу. Чтобы вернуть машину, удалите агента и подключите заново кодом.
- **Удалить** — для агента без связи или отключённого: он пропадает из списка, история его выгрузок остаётся.

Здесь же блок **«Что делают сейчас»** — какой Revit какую модель открыл, с кнопками **«Отменить»** и **«Убить»**. Зачем они — [Обзор → Убить зависший Revit](Dashboard#убить-зависший-revit).

## Источники

**Ферма → Источники моделей.** Откуда расписания всех модулей берут модели.

| Тип | Поля |
|---|---|
| **Revit Server** | **Имя или адрес Revit Server** (например `srv-rs22`), **Версия Revit** — сервер обслуживает одну версию, **Корневая папка на сервере** — пусто, чтобы видеть весь сервер |
| **Сетевая папка** | **Папка** — UNC-путь, например `\\nas\Проекты`. Версия Revit берётся из каждого файла |

Дерево источника читает агент, поэтому адрес должен быть доступен **с машин с Revit**. Повторяем это на каждой странице, потому что об это спотыкаются все.

## Именование моделей

**Ферма → Именование моделей.** Справочник: как из имени модели получить объект, раздел, часть здания и свои поля.

Им пользуются все: проверка LOI (аналитика и профиль по разделу), коллизии (разделы моделей части) и пользователи (список разделов при регистрации). Поэтому справочник лежит в Ферме и работает, даже если модуль LOI выключен. Смотреть может любой, кроме проектировщика, менять — администратор.

Разделители, записи по полям, шаблоны кусков, выражения на имя целиком, предпросмотр на моделях сервиса и кнопка «Стандартный справочник» — на отдельной большой странице [Разбор имён моделей](Model-naming).

После правки справочника записанные проверки LOI можно пересчитать: **Проверка LOI → Настройка аналитики → «Пересчитать аналитику по справочнику»**.

## Пресеты выгрузки

**Выгрузка → Пресеты.** Именованные наборы параметров RVT и NWC — чтобы не выставлять двадцать галочек в каждом расписании. Один пресет — **по умолчанию**: он подставляется в новое расписание. Расписание может переопределить любой параметр пресета для себя.

**Открытие**

| Параметр | Что делает |
|---|---|
| **Не загружать связи** | Модель копируется во временную папку агента, в копии связи помечаются «не загружать». Открытие быстрее, исходник не меняется |
| **Проверка при открытии (Audit)** | Revit проверяет и исправляет модель при открытии — заметно дольше |
| **Не открывать рабочие наборы, содержащие** | Рабочие наборы с этим словом в имени остаются закрытыми; их элементов нет в NWC |

**RVT — обработка перед сохранением:** удалить связи RVT, удалить CAD, удалить облака точек, очистить неиспользуемое (доступно с Revit 2024), сжать файл. Модели совместной работы сохраняются как отсоединённые файлы хранилища с локальной копией.

**NWC:** имя 3D-вида для экспорта (по умолчанию `Navisworks`), общие координаты, параметры элементов, разделение по уровням, связанные файлы и CAD, части, геометрия помещений и помещения как атрибут, источники света, идентификаторы элементов, ссылки (URL), поиск отсутствующих материалов, коэффициент фасетизации.

> [!NOTE]
> Если в модели нет вида с заданным именем, NWC пропускается с пояснением в истории. Самая частая причина «а где мой NWC?» — вид называется `Navisworks ` с пробелом на конце или `navis`. Revit к пробелам относится серьёзно.

## Профили LOI

**Проверка LOI → Профили.** Правила проверки заполнения параметров — те же профили, что в плагине ParamChecker. Меняют их координатор и администратор.

- **Загрузить из ParamChecker** — добавить профили из файла плагина. Одноимённые получают номер, ничего не перезаписывается; модели из файла не переносятся.
- **+ Новый профиль** и щелчок по профилю — редактор: вид по умолчанию, рабочие наборы, которые не открывать, и правила (какие элементы отобрать и какие параметры у них проверить).
- **Группы** — профили раскладываются по группам, обычно по проектам; внутри группы имена уникальны. Группу можно переименовать целиком, профиль — скопировать в другую группу.
- **Скачать** — файл с одним профилем, который плагин импортирует обратно.
- **Удалить** — профиль, который выбран хотя бы в одном расписании, удалить нельзя.
- **готов / не готов** — можно ли проверять этим профилем; на пометке «не готов» написано, чего не хватает.
- **Каталог Revit для редактора правил** — внизу страницы: кнопка **«Обновить из Revit»** снимает категории и параметры в Revit на агенте, чтобы редактор подсказывал названия.

Подробно, с примерами правил и операторов — [Профили LOI](LOI-profiles).

## Аналитика LOI

**Проверка LOI → Настройка аналитики.**

> [!NOTE]
> Это **настройки**. Страница с графиками — **Проверка LOI → Аналитика**, см. [Аналитика LOI](Analytics). Да, названия похожи. Нет, это не одно и то же.

Смотреть может любой пользователь, кроме проектировщика, менять — только администратор. На странице два блока:

| Блок | Что там | Подробно |
|---|---|---|
| **Аналитика LOI** | Флажок **«Сохранять итоги проверок и показывать аналитику»**, **«Хранить проверки, лет»** (0 — всегда) и кнопка **«Пересчитать аналитику по справочнику»** | [Аналитика LOI](Analytics#включить-выключить-срок-хранения) |
| **Ручные поправки моделей** | Объект, раздел, часть или заказчик конкретной модели — главнее справочника | [Ручные поправки](Model-naming#ручные-поправки-моделей) |

Справочник именования моделей отсюда переехал в **Ферма → Именование моделей**: он общий для всех модулей.

## Хранение и пороги коллизий

**Коллизии → Параметры.** Меняет администратор.

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| **Сколько выгрузок хранить у каждой модели** | 3 | Лишние старые слепки удаляются сразу. Слепки видимого результата черновика и удачных утверждённых прогонов за последние 14 дней не удаляются |
| **Выгрузка устарела — дней** | 7 | Модель с более старым слепком попадает в «Обзор проверок» |
| **Давно не прогонялась — дней** | 7 | Утверждённая проверка без прогона дольше срока |
| **Всплеск — доля новых от активных, %** | 10 | Прогон, в котором новых коллизий больше этой доли и не меньше порога ниже, отмечается всплеском |
| **Всплеск — и не меньше новых** | 50 | Второе условие всплеска: чтобы три новые коллизии при двадцати активных не считались катастрофой |
| **Висят — дней без движения** | 30 | Открытая коллизия без записей в ленте дольше срока |

Порог «агенты не в сети» стал общим и переехал в **Администрирование → Сервер**.

Как пороги показываются — [Коллизии → Обзор проверок](Clash#обзор-проверок).

## Семейства

**Семейства → Параметры.** Здесь задаётся всё про библиотеку: корень библиотеки, папка проверки, интервал обхода, агент библиотеки; ниже — **направления BIM** (кто делает заявки каких разделов) и срок **автоприёмки** заявок. Меняет администратор.

Подробно — [Семейства → Для администратора](Families#для-администратора) и [Направления BIM](Families#направления-bim).

## Пользователи

**Администрирование → Пользователи.**

| Роль | Что может |
|---|---|
| **Проектировщик** | Коллизии: «Мои», проверки, отчёты и сводка; статус и «кто правит» — в коллизиях своих разделов. Семейства: каталог и заявки. См. [Проектировщику](Designer) |
| **Наблюдатель** | Смотрит «Обзор», модули, Ферму и в Администрировании — модули, сервер и журнал действий; ничего не меняет |
| **Координатор** (в API — `Operator`) | Плюс расписания, пресеты и профили LOI, запуск, отмена и повтор заданий, «Убить» Revit; настройка, утверждение и прогон проверок коллизий, любые действия с коллизиями; порядок в библиотеке семейств и заявки; подтверждение заявок на регистрацию, разделы пользователей |
| **Администратор** | Плюс агенты, источники, именование моделей, пользователи и общие настройки |

Наблюдатель → координатор → администратор — лесенка: каждая роль умеет всё, что предыдущая, и чуть больше. Проектировщик стоит особняком: он не «младший наблюдатель», а человек со своим узким рабочим местом.

**Заявки на регистрацию** — блоком над списком. Проектировщики регистрируются сами; заявку подтверждает или отклоняет координатор, неподтверждённая удаляется через 3 дня.

**Список:** имя (с логином и должностью), роль, разделы, состояние (активен, отключён), последний вход, когда создан. Сортировка по любому столбцу, поиск по имени, логину и должности, фильтры по роли, разделу и состоянию.

**Действия над выбранными.** Отметьте пользователей флажками (флажок в заголовке выбирает всех, кто сейчас виден по фильтрам) и выберите действие:

- **Добавить раздел** / **Убрать раздел** — координатор и администратор;
- **Отключить** / **Включить** — администратор.

Себя и последнего активного администратора массовое «Отключить» не трогает; кого пропустили и почему, показывается над списком. Запереть систему снаружи, оставшись внутри без администратора, у вас не получится — мы проверяли.

Щелчок по пользователю открывает карточку: контакты и разделы правит координатор; роль, пароль, отключение и удаление — администратор. Пароль — не короче 6 символов.

**Про входы и токены:**

- Смена пароля или роли и отключение пользователя завершают все его входы в браузере.
- ToadTools работает с ToadFlow по личному токену компьютера: токен выдаётся при входе в окне ToadTools «Подключение к ToadFlow» и отзывается кнопкой «Выйти» там же.
- Токены ToadTools не действуют, пока пользователь отключён; смена пароля их **не** отзывает.

## Модули

**Администрирование → Модули.** Какие модули есть на сервере, включён ли каждый и на связи ли его рабочий процесс (у коллизий — движок коллизий).

Переключателей тут нет, и это намеренно: набор модулей задаётся при установке строкой `MODULES` в `.env` — см. [Сервер → Выбор модулей](Server#выбор-модулей). Выключить коллизии всей компании случайным щелчком — сомнительное удобство.

## Общие

**Администрирование → Сервер.** Вверху — состояние сервера: версия, сколько работает, размер базы, память, свободное место на томах с данными, рабочие процессы модулей. Ниже — общие настройки (меняет администратор):

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| **Часовой пояс** | Europe/Moscow | По нему считаются расписания, дни на графике и `{дата}` в папке результатов |
| **Таймаут на модель по умолчанию, мин** | 30 | Подставляется в новые расписания |
| **Молчание Revit до перезапуска, мин** | 10 | Revit, который столько не подаёт признаков жизни, считается зависшим: агент убивает его, модель повторяется |
| **Перезапускать Revit после, моделей** | 20 | Плановый перезапуск Revit, чтобы не копились утечки памяти |
| **Или когда Revit занял, МБ** | 12000 | То же — по занятой памяти |
| **Хранить логи, дней** | 90 | Сколько хранить закончившиеся запуски, их логи и журнал действий |
| **Агенты не в сети — минут** | 10 | Агент молчит дольше — плашка в «Требует внимания» на «Обзоре» и предупреждение в обзоре проверок коллизий. От 1 до 10 080 |

Изменения сразу отправляются всем агентам — перезапускать ничего не нужно.

> [!TIP]
> Если у вас модели-тяжеловесы, которые честно молчат по пятнадцать минут на открытии, поднимите «Молчание Revit до перезапуска». Иначе агент будет исправно убивать Revit, который просто думал.

## Журнал действий

**Администрирование → Журнал действий.** Кто и когда что менял: расписания, пользователи, настройки, агенты, ручные запуски и отмены. Столбцы «Когда», «Кто», «Что»; фильтры — кто (часть имени), вид события, период.

Записи хранятся столько же, сколько логи (**Хранить логи, дней**).
